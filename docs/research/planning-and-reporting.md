# How much project management does this pilot need?

In the original Copilot intake pilot, a PM could answer a delivery question with a browser. The costly mistake was asking the wrong record: the milestone counted seven open items, the issue report counted five open issues, and neither count explained why Copilot intake had stopped. Start with the board for current work, follow the issue for the decision, and generate a snapshot when someone needs to reconstruct a milestone. [Experiment results and replay](experiments.md)

## What the reference implementation adds

GitHub already stores the work breakdown, dependency graph, review evidence and status transitions. A new PM needs to know which record answers “what can we do while we wait?” The pilot contributes a worked example: a real access blocker, an independent deliverable that proceeded, and a checked candidate awaiting a human decision. A team already using these conventions can adopt the guide without deploying software. The incremental value of installing the reporter is narrower: producing a reproducible, public, issue-level milestone snapshot that includes missing board items.

The original README already linked to the board. Its installation instructions appeared before its project-cycle guidance. The revised entry point leads directly to the decision and the evidence. Routine updates can link to a live record. A dated decision can carry one reviewed snapshot. Republishing the same table on the parent and in a Project update adds another copy that can age independently. [Original snapshot](https://github.com/niikei/agentic-pm/issues/5#issuecomment-7199354981) · [PM guide change](https://github.com/niikei/agentic-pm/pull/13)

## What the research changes about the recommendation

A controlled study of 16 experienced developers and 246 tasks found longer completion times with the early-2025 tools it evaluated. Perceived speed and measured delivery time diverged. Count coordination work and review separately before claiming a velocity gain here. [METR study](https://metr.org/Early_2025_AI_Experienced_OS_Devs_Study-paper.pdf)

A study of asynchronous agents found accuracy gains from isolated workspaces, central delegation and tested integration on PaperBench and Commit0. That motivates assigning independently checkable outputs. The workshop exercise tested handoff fidelity; it cannot establish the same effect on software delivery. [Asynchronous agent study](https://arxiv.org/abs/2603.21489)

A requirements-flow case study based on 43 interviews reported perceived flexibility gains alongside overcommitment and difficulty balancing planning effort. The relevant move at this scale is to revise the affected decision when evidence changes and let independent work continue. A standing replan meeting or scheduling algorithm would need its own evidence. [Ericsson case study](https://doi.org/10.1007/s10664-016-9491-z)

## Prioritized roadmap

The v0.1 milestone covers the shared GitHub workflow and the first Codex-led issue-to-PR cycle. Review the live dependency graph, board transitions, hosted checks and candidate handoff against the [release criteria](https://github.com/niikei/agentic-pm/issues/5). The maintainer records the [release decision](https://github.com/niikei/agentic-pm/issues/7).

Copilot native intake remains an independent [compatibility trial](https://github.com/niikei/agentic-pm/issues/3). Claude Code has a separate [proposed trial](../agent-profiles.md#claude-code). Record each agent's actual results before extending its support claim.

For subsequent adoption, observe a PM finding independent work and verification evidence from the board. At a real handoff, record whether the joined report or event digest informed a decision. Revisit native auto-add if another issue misses its Project, and compare Project copy with manual setup when a second team adopts the process. These observations can guide future scope decisions.
